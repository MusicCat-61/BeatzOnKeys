## Правило «газ»

Это главный рабочий ритуал, и он важнее любой спешки.

1. Когда пользователь просит новую функцию или правку, я **сначала предлагаю план** и спрашиваю: «добавить что-то ещё?»
2. **Ничего не реализую и не выпускаю**, пока не прозвучит слово **«газ»**.
3. Только после «газ» — код, проверки и релиз.
4. Если пользователь говорит «запиши к себе» — это **не** «газ». Это значит: положи в очередь и жди. Записывать в очередь и браться в работу — разные вещи.

## Как выпускается релиз

Каждый раз один и тот же порядок:

1. Сборка: `dotnet build BeatzOnKeys.sln -c Release` — ноль ошибок, ноль предупреждений.
2. Тесты ядра: `dotnet run --project BeatzOnKeys.Tests` — все зелёные.
3. UI smoke: `dotnet run --project tools/UiSmoke -- --root . --session <имя>`.
4. Production-трей: то же с `--production-tray`, ожидание 11 PASS / 0 FAIL.
5. Заметки к релизу: `release-notes/vX.Y.Z.md` на двух языках с таблицами ассетов.
6. Скриншоты в `assets/` — переснять из свежего прогона.
7. Коммит, тег, пуш `main` и тега.
8. Дождаться workflow и проверить **4 ассета** в релизе.

Перед запуском smoke убивать висящие процессы `*Beatz*` и ждать несколько секунд: приложение должно быть в одном экземпляре.

## О чём помнить в этом проекте

- Версия правится в пяти `csproj`, `app.manifest`, `publish.bat`, `AboutWindow.xaml.cs`, `tools/AudioProbe/Program.cs`, `UpdateServiceTests`, обоих README и файле заметок. `AssemblyVersion` — максимум четыре части.
- Установленную копию не бампать и не запускать.
- В XAML/XML править через `[System.IO.File]::ReadAllLines` / `WriteAllLines` с `UTF8Encoding($false)` и явными индексами, потом проверять `XmlDocument.Load`.
- Сообщения коммитов с кавычками — только через файл (`git commit -F`), иначе PowerShell их портит.
- `git push` заканчивается `[exit code: 1]` из-за CRLF-предупреждений — смотреть на строки `main -> main` и `[new tag]`, а не на код возврата.
- Не советовать VPN. Про блокировки говорить честно и проверять причину, а не пересказывать формулировку чужого инструмента.

## Уроки, за которые уже заплачено

- **Плашка, обвиняющая провайдера, была неправдой.** `statusCode: 10204` — это ответ самого TikTok, а фраза про «IP address is blocked» — перевод yt-dlp. Причину надо читать из ответа сервиса, а не из чужого текста.
- **Кнопка без текста прожила четыре релиза.** Скриншот не заменяет проверку: если элемент важен, у него должно быть утверждение в smoke.
- **Кодировка.** Python-утилиты на Windows пишут в кодировке консоли; читать их вывод как UTF-8 нельзя. Нужен `PYTHONIOENCODING=utf-8`, а на выходе — вычистка символов замены.
- **«Записать в очередь» ≠ «сделать».** Это правило про «газ», и оно уже нарушалось.
- **Команда с `CanExecute` без `NotifyCanExecuteChanged` — мёртвая кнопка.** Крестик фильтра в YouTube и TikTok не нажимался: сеттер поля поднимал свойство, но WPF не переспрашивает `CanExecute` сам. Любая команда с условием обязана уведомлять о смене состояния, и у каждой кнопки-иконки должно быть утверждение в smoke.
- **Замер вместо обещания.** Фраза «TikTok отдаёт embed без регионального отказа» прожила два релиза, потому что smoke работает на подставном сервисе и настоящей сети не касается. Внешний маршрут считается существующим только после живого прогона через настоящий код.
- **«Не пусто» — не проверка.** Счётчик «Кеш TikTok» два релиза показывал `0 КБ` при непустой папке: getter подставлял ноль, когда число ещё не измеряли, а `TikTok.InitializeAsync()` не вызывался при старте вообще. Smoke это пропускал, потому что утверждение требовало лишь «метка не пустая». Проверять надо **значение**: сверять с тем, что реально на диске, и требовать, чтобы «неизвестно» отличалось от «ноль».

## Позиционирование

**BeatzOnKeys — фокус-плеер, который подстраивается под твой ритм.** Не «печать под музыку» и не «плеер с фичей громкости». Продукт для людей, которым музыка помогает работать, но мешает думать, — в первую очередь для СДВГ-аудитории.

Этот угол **не откатывать**. Будущий агент, который переписывает README, заметки или тексты интерфейса, обязан держаться этих правил:

1. **Сначала ценность, потом механика.** «Музыка, которая знает, когда ты работаешь» — и только затем таймауты, хуки и задержки в 50 мс.
2. **Убирать решения, а не добавлять настройки.** Каждый экран должен снижать число выборов. Стартовый экран отвечает на один вопрос — откуда сегодня музыка. Фокус-режим убирает всё, кроме трека и транспорта.
3. **Никакой геймификации и оценок себя.** Ни уровней, ни достижений, ни «сегодня 2 ч 40 мин в фокусе». СДВГ-человек получает оценки отовсюду; приложение не добавляет ещё одну.
4. **Числа — только про музыку.** «Треков: 3» — да. «Сколько ты работал» — нет.
5. **Инструмент, а не медицинская помощь.** Никогда не писать «лечит СДВГ», «терапия», «клинически доказано». Формулировка: помогает некоторым людям удерживать ритм работы.
6. **Не продаём музыку и не требуем подписку.** Свои файлы и свои ссылки. Это обещание живёт в README обоих языков.

### Что поддерживает угол

| Элемент | Зачем он здесь |
|---|---|
| Стартовый экран с плитками | один вопрос вместо четырёх вкладок |
| Приветствие по времени суток | приложение знает, что ты человек, а не сценарий |
| Режим «Фокус» | убирает вкладки, кеши, счётчики, плашки и настройки |
| «Не смолкать» в фокусе | тишина не наступает неожиданно |
| Карточка «Продолжить» на хабе | одно действие, не требующее выбора |
| Строка статуса крупным шрифтом | ответ на «что вообще происходит» |

Если новая фича не поддерживает ни один из этих пунктов и не убирает решение — она, скорее всего, не нужна.
