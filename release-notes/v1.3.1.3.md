## English

1.3.1.3 lets an interrupted update download continue instead of starting over.

### The download survives an interruption

- **Closing the window, losing the connection, or killing the app no longer throws away what was already downloaded.** The partial file is kept, and the next attempt asks the server for the rest with an HTTP range request, appending to the bytes on disk.
- **The progress starts where it stopped.** A resumed download shows the real position, because the bytes already present count toward the total.
- **A file that turns out complete needs no network at all**: it goes straight to the checksum, so a crash right before verification costs nothing.

### When it still starts over

- **Wrong bytes are discarded.** A checksum mismatch deletes the partial, because keeping it would only fail the same check next time.
- **A server that ignores the range request restarts the transfer**, which is what that answer means.
- **A partial larger than the asset is junk from another build** and is replaced rather than extended.
- **Partials from other versions are swept away** when a new download starts, so they cannot pile up as half-finished builds.

## Русский

1.3.1.3 позволяет прерванному скачиванию обновления продолжиться, а не начинаться заново.

### Загрузка переживает прерывание

- **Закрытие окна, обрыв связи или завершение приложения больше не выбрасывают уже скачанное.** Частичный файл сохраняется, и следующая попытка запрашивает у сервера остаток через HTTP range, дописывая к тому, что уже лежит на диске.
- **Прогресс начинается с того места, где остановился.** Докачка показывает настоящую позицию, потому что уже имеющиеся байты учитываются в общем размере.
- **Файл, который оказался полным, вообще не требует сети**: он сразу идёт на проверку контрольной суммы, так что падение прямо перед проверкой ничего не стоит.

### Когда всё же начинается заново

- **Неверные байты отбрасываются.** Несовпадение контрольной суммы удаляет частичный файл: хранить его бессмысленно, следующая проверка провалится так же.
- **Сервер, который игнорирует range-запрос, перезапускает передачу** — именно это и означает такой ответ.
- **Частичный файл больше самого ассета** — мусор от другой сборки, его заменяют, а не дописывают.
- **Обрывки от других версий удаляются** при старте новой загрузки, чтобы не копились недокачанные сборки.
