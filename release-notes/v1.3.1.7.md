## English

1.3.1.7 actually shows the folder question. The dialog was written, translated and wired into a method — but the method was never called.

### Why nothing was asked

- **`OfferStorageFolder()` existed and did nothing, because no line called it.** The decision logic was correct: a copy on the desktop asks where its data should live. The question simply never reached the screen, so the run silently fell back to `%LOCALAPPDATA%` and created a folder there.
- **It is now called right after the main window is shown**, which is the point where the question has context and a theme to draw with.

### What is verified now

- **The desktop is resolved through the shell, and a test asserts the lookup answers.** A silent empty result would have made every desktop copy look portable, and that failure mode is now caught.
- **A smoke check calls the method and confirms it returns immediately when the mode is pinned**, so a missing or renamed entry point fails the run instead of quietly doing nothing.

## Русский

1.3.1.7 действительно показывает вопрос о папке. Диалог был написан, переведён и завёрнут в метод — но метод никто не вызывал.

### Почему ничего не спросилось

- **`OfferStorageFolder()` существовал и ничего не делал, потому что его никто не вызывал.** Логика решения была верной: копия с рабочего стола спрашивает, где хранить данные. Вопрос просто не доходил до экрана, поэтому запуск молча сваливался в `%LOCALAPPDATA%` и создавал там папку.
- **Теперь он вызывается сразу после показа главного окна** — там, где у вопроса есть контекст и тема для отрисовки.

### Что теперь проверяется

- **Рабочий стол определяется через оболочку, и тест утверждает, что запрос отвечает.** Молчаливый пустой результат сделал бы любую копию с рабочего стола «портативной», и теперь такой отказ ловится.
- **Проверка в смоуке вызывает метод и подтверждает, что при закреплённом режиме он сразу выходит**, так что пропавшая или переименованная точка входа валит прогон, а не молчит.
