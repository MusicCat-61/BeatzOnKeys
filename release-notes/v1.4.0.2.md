## English

1.4.0.2 makes TikTok downloads work without a VPN. The "video deleted or private" message was wrong almost every time: the file was being saved under a temporary name and then thrown away, and the wall TikTok puts in front of some requests can be opened by solving the small puzzle it carries.

### The file keeps the name the player expects

- **The `.part` suffix was never replaced.** A finished MP3 called `123.part` was handed to a player that only accepts `.mp3`, `.wav` and `.m4a`, so it was refused, deleted, and the user was told TikTok had sent an unplayable format. The rename now happens the moment the transfer finishes.
- **Nothing is deleted on the first failure any more.** The file stays where it is, so the next attempt can reuse it and a bug report can show what TikTok actually sent.

### The interception page is solved, not feared

- **TikTok answers some requests with a "Please wait" page carrying a small proof of work.** The program finds the number whose hash matches, which takes milliseconds on a real challenge and a third of a second in the worst case the budget allows, and asks again with the key. No browser, no JavaScript engine, no external tool.
- **The key is reused for the rest of the download** and travels on the very first request of every later page, so the puzzle is not solved twice and the rate limiter is not poked for nothing.
- **A puzzle that keeps coming back is reported as a refusal** after one retry, and a puzzle harder than the budget is written to the log instead of looking like a broken site.

### The right stream, and the honest reason

- **The separate audio track is asked for first**, the H.264 video is the fallback, and the H.265 variants are no longer touched: those need a separate HEVC package that most machines do not have, which is exactly how a decodable file turned into "format not supported".
- **A short link that answers with the puzzle instead of a redirect still resolves**, because the page is read through the unlocking path and the redirect is followed once more after that.
- **"Your provider is blocking TikTok" is now its own message**, taken from yt-dlp's own words, with a plate that appears only after it really happened and a cross to put it away.

### A path that was written into the text

- **The guide no longer claims `%LOCALAPPDATA%`.** The file list is built from the root the program is actually running from, so a portable copy finally shows its own folder, and it mentions `library.json` and `Music\TikTok\`.

## Русский

1.4.0.2 заставляет скачивание из TikTok работать без VPN. Сообщение «видео удалено или закрыто» почти всегда было неправдой: файл сохранялся под временным именем и тут же выбрасывался, а стену, которую TikTok ставит перед частью запросов, можно открыть, решив небольшую задачку, которая в ней лежит.

### Файл получает имя, которого ждёт плеер

- **Суффикс `.part` никуда не девался.** Готовый MP3 с именем `123.part` отдавался плееру, который принимает только `.mp3`, `.wav` и `.m4a`, — тот отказывался, файл удалялся, а пользователю сообщали, что TikTok прислал невоспроизводимый формат. Теперь переименование происходит сразу после докачки.
- **При первой неудаче ничего не удаляется.** Файл остаётся на месте: следующая попытка может им воспользоваться, а отчёт о проблеме — показать, что именно прислал TikTok.

### Заглушка решается, а не пугает

- **На часть запросов TikTok отвечает страницей «Please wait» с небольшой задачкой.** Программа находит число, хеш которого совпадает с целевым: на настоящем челлендже это миллисекунды, в худшем допустимом случае — треть секунды. Потом запрос повторяется с ключом. Ни браузера, ни JavaScript-движка, ни внешних утилит.
- **Ключ переиспользуется до конца скачивания** и уходит уже в первом запросе каждой следующей страницы, чтобы не решать задачку дважды и лишний раз не злить ограничитель частоты.
- **Задачка, которая возвращается снова, считается отказом** после одной повторной попытки, а задачка сложнее бюджета попадает в журнал, чтобы это не выглядело как «TikTok сломался».

### Нужный поток и честная причина

- **Сначала запрашивается отдельная звуковая дорожка**, резерв — видео H.264, а варианты H.265 больше не трогаются: им нужен отдельный пакет HEVC, которого на большинстве машин нет, — именно так нормальный файл превращался в «формат не поддерживается».
- **Короткая ссылка, ответившая заглушкой вместо редиректа, всё равно раскрывается**: страница читается через тот же путь с разблокировкой, а редирект повторяется после неё.
- **«Провайдер не пускает к TikTok» стало отдельным сообщением**, взятым из собственных слов yt-dlp, с плашкой, которая появляется только после реального отказа, и крестиком, чтобы её убрать.

### Путь, который был вписан в текст

- **Гайд больше не утверждает `%LOCALAPPDATA%`.** Список файлов строится из корня, в котором программа действительно работает, так что портативная копия наконец показывает свою папку, и в нём упомянуты `library.json` и `Music\TikTok\`.
