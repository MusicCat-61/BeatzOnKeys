## English

1.4.0.6 makes each tab play its own queue, adds search fields with a working cross to all three lists, lets a TikTok track be renamed and dragged, remembers the window size you drag it to, and gives TikTok a route that actually works when the site refuses your connection — with an honest correction of what 1.4.0.2 and 1.4.0.5 claimed.

### Each tab plays its own queue

- **The queue now belongs to the page you are on.** Playing a track on YouTube advances to the next *YouTube* track; the local playlist is not pulled in, and its own next-track order stays untouched.
- **`Loop` wraps inside the page** instead of wandering into another list, and a page switch never stops what is already playing — the playing track is kept at the top of the new queue.
- **Previews never join the queue.** A preview is a listen, not a decision.
- **The "now playing" card names the real source.** It used to show the wrong tab whenever a track started from a list the program had not clicked through; the label is now derived from the lists themselves, so it cannot drift.

### Search fields, with a cross that works

- **All three lists — local, downloaded YouTube, downloaded TikTok — have a field above them.** Typing filters the visible rows only: counters, buttons and the queue keep working on the full list, so a filter can never look like a deletion.
- **The cross clears the field**, and it was broken: the command was declared with a condition, and nothing told the interface to re-check that condition, so the button stayed disabled and a click did nothing. It now reports its state, and the smoke presses every cross in the window to prove it.
- **The cross is bigger** (28×28 instead of 24×24) and the "nothing found" hints are two points larger.
- **"Nothing matched" is a separate line**, so an empty result never reads as "you have no tracks".

### Renaming a TikTok track

- **The pencil in the row** starts an edit; `Enter` confirms, `Esc` cancels, clicking elsewhere confirms. Double-click is deliberately not used.
- **Only the name in the list changes** — the file on disk keeps its name, and the change survives a restart.
- **A blank name is refused** rather than leaving an unnamed row.

### Typing into a field behaves

- **200 characters maximum, one line only.** A pasted playlist description with line breaks is flattened to a single line instead of breaking the layout.

### Reordering TikTok tracks

- **Drag a row to move it**, with an insertion line showing where it will land. Dropping a row onto itself, or outside the list, changes nothing.

### The window remembers its size

- **The size you drag it to is used at startup.** It only ever grows: shrinking the window is not recorded, so a temporary small size cannot become the permanent one.
- **A maximised window is not remembered** as a size, because that is a state, not a measurement.

### Two dialogs had the wrong title

- **"Clear downloaded" and "Clear search cache" showed the cache title.** Each button now names its own action.

### TikTok: the route that works, and a correction

- **A last-resort relay, `tikwm.com`, is asked when TikTok itself refuses the clip.** It returns a direct address on TikTok's own media host — the part that stays reachable when the web endpoints do not — and the file is downloaded from there.
- **Measured on three live clips with no VPN and no proxy:** 10.20 s, 20.49 s and 9.95 s, all decoded and playable. The relay's free tier allows one request per second, so the program waits and retries exactly once.
- **Only https addresses on TikTok media hosts are downloaded.** If the relay names any other host, it is ignored: this program must not become a downloader for whatever address a third party chooses.
- **`music_info.title` is used only when it is a name.** "original sound - …" and its translations are not track names, so the clip's own description is used instead.
- **Correction:** 1.4.0.2 and 1.4.0.5 said TikTok worked "without a VPN" as a settled fact. That was never verified — the smoke suite runs against a stand-in service and never touches the network — and it is not true in general: TikTok decides by connection, and the embed route answers 400 on a refused one. The claim is withdrawn here; the older notes are left as they were written.
- **The message you see on a refusal is unchanged and honest:** TikTok does not serve this clip to your connection, it is TikTok's own restriction, and another network may open it. The program does not blame your provider and does not advertise a way around it.

### Fixed along the way

- **A window size saved as 0×0.** The settings writer copies fields by name, so the two new size fields were silently dropped; the writer now carries them.
- **Playlist selection lost after a reorder.** The filters returned a fresh list on every change, which reset the selection; they now refresh a view instead.

## Русский

1.4.0.6 даёт каждой вкладке свою очередь, добавляет поля поиска с работающим крестиком во все три списка, позволяет переименовать и перетащить трек TikTok, запоминает размер окна, до которого вы его растянули, и даёт TikTok маршрут, который действительно работает, когда сайт отказывает вашему подключению, — вместе с честной поправкой к тому, что обещали 1.4.0.2 и 1.4.0.5.

### Каждая вкладка играет свою очередь

- **Очередь теперь принадлежит странице, на которой вы находитесь.** Трек на YouTube переходит к следующему *YouTube*-треку; плейлист «Локально» при этом не подмешивается, и его собственный порядок остаётся нетронутым.
- **`Loop` замыкается внутри страницы**, а не уходит в другой список, и переключение страницы никогда не останавливает то, что уже играет: играющий трек остаётся первым в новой очереди.
- **Предпрослушивание не попадает в очередь.** Это прослушивание, а не решение.
- **Карточка «сейчас играет» называет настоящий источник.** Раньше она показывала не ту вкладку, если трек запускался из списка, по которому программа не «кликала»; теперь подпись выводится из самих списков и разойтись не может.

### Поля поиска, и крестик в них работает

- **Все три списка — локальный, скачанные YouTube и скачанные TikTok — получили поле сверху.** Ввод фильтрует только видимые строки: счётчики, кнопки и очередь продолжают работать с полным списком, поэтому фильтр не может выглядеть как удаление.
- **Крестик очищает поле**, и он был сломан: команда объявлена с условием, а интерфейсу никто не сообщал, что условие изменилось, поэтому кнопка оставалась недоступной и клик ничего не делал. Теперь она сообщает о своём состоянии, а smoke нажимает каждый крестик в окне, чтобы это подтвердить.
- **Крестик стал крупнее** (28×28 вместо 24×24), а подписи «ничего не нашлось» — на два пункта больше.
- **«Ничего не нашлось» — отдельная строка**, поэтому пустой результат никогда не читается как «у вас нет треков».

### Переименование трека TikTok

- **Карандаш в строке** запускает правку; `Enter` подтверждает, `Esc` отменяет, клик в стороне подтверждает. Двойной щелчок намеренно не используется.
- **Меняется только название в списке** — файл на диске сохраняет своё имя, а правка переживает перезапуск.
- **Пустое название не принимается**, чтобы в списке не появилась безымянная строка.

### Ввод в поле ведёт себя прилично

- **Максимум 200 символов, только одна строка.** Вставленное описание плейлиста с переводами строк выравнивается в одну строку, а не ломает разметку.

### Порядок треков TikTok

- **Строку можно перетащить**, и линия вставки показывает, куда она встанет. Бросок строки на себя или мимо списка ничего не меняет.

### Окно помнит свой размер

- **Размер, до которого вы его растянули, используется при запуске.** Он может только увеличиваться: уменьшение не записывается, поэтому случайно маленький размер не станет постоянным.
- **Развёрнутое окно не запоминается** как размер: это состояние, а не измерение.

### У двух диалогов был неверный заголовок

- **«Очистить скачанные» и «Очистить кеш поиска» показывали заголовок кеша.** Теперь каждая кнопка называет своё действие.

### TikTok: работающий маршрут и поправка

- **Последняя попытка — посредник `tikwm.com`**, к нему программа обращается, когда сам TikTok отказывает. Он возвращает прямой адрес на медиа-хосте TikTok — той части, что остаётся доступной, когда веб-адреса нет, — и файл скачивается уже оттуда.
- **Замерено на трёх живых роликах без VPN и без прокси:** 10.20 с, 20.49 с и 9.95 с, все декодируются и играются. Бесплатный тариф посредника разрешает один запрос в секунду, поэтому программа ждёт и повторяет ровно один раз.
- **Скачиваются только адреса `https` на медиа-хостах TikTok.** Если посредник назовёт любой другой хост, он игнорируется: программа не должна становиться загрузчиком того адреса, который выбрала третья сторона.
- **`music_info.title` берётся, только если это название.** «original sound - …» и его переводы названием трека не являются, поэтому вместо них используется описание самого ролика.
- **Поправка:** в 1.4.0.2 и 1.4.0.5 было сказано, что TikTok работает «без VPN», как о решённом факте. Это никогда не проверялось — smoke работает на подставном сервисе и настоящей сети не касается, — и в общем случае это неправда: TikTok решает по подключению, а embed-маршрут на отказанном отвечает 400. Обещание снимается здесь; старые заметки оставлены такими, какими были написаны.
- **Сообщение при отказе не изменилось и остаётся честным:** TikTok не отдаёт этот ролик вашему подключению, это его собственное ограничение, и с другой сети он может открыться. Программа не обвиняет провайдера и не рекламирует способ обойти запрет.

### Попутно исправлено

- **Размер окна сохранялся как 0×0.** Запись настроек копирует поля по именам, поэтому два новых поля размера молча терялись; теперь они переносятся.
- **Выделение в плейлисте терялось после перетаскивания.** Фильтры возвращали новый список при каждом изменении, что сбрасывало выделение; теперь они обновляют представление.
